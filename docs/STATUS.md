## Important constraints

- The selected baseline backend is LLVM `llc`; QBE is not implemented or reported as
  supported.
- The scanner is generated by GNU Flex from `src/lexer.l`; the handwritten
  recursive-descent parser and all later compiler stages remain C++.
- The compiler accepts `.cm` and `.c` input but does not invoke a preprocessor.
- GCC is only used by the execution test to assemble generated `.s` and link generated
  `.o`; the UI's Run program action follows the same assembly/link steps and never
  sends C Minor source to GCC.
- The compiler currently supports string and single-byte character literals, and a
  built-in variadic `printf` accepting a format literal followed by integer
  arguments. This remains a restricted language, not a general C implementation.
- Windows frontend test results do not prove the required Linux x86-64 ABI behavior.
- Do not describe the project as SRS-complete until `make test-execution` and the
  required traceability/evidence work have passed.
